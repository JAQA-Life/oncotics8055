# Research safeguards

- **FACT:** provider-returned field with acquisition receipt and raw payload. This is attribution, not independent clinical confirmation.
- **DERIVED:** documented alias hint, query-match edge, coordinate transformation or deterministic report compilation. Query matches do not establish causality.
- **ASSUMPTION:** researcher hypothesis or unverified imported provider attribution.
- **SIMULATED:** every synthetic stakeholder profile, generated statement, model-selected reference and simulation graph. A model cannot promote its output to FACT.

Review source records, retrieval failures and assumptions before running. Generated references must point to seed records, but citation relevance and statement truth are not verified by that structural check. Source titles can contain misleading instructions; prompts treat them as untrusted data, but prompt-injection resistance is not guaranteed.

No efficacy, safety, patient outcome, trial eligibility, regulatory approval, dosimetry or geographic prediction is validated or supported. No patient information or confidential material is permitted. The UI requires public-data/research-use confirmation and evidence review. There is no DICOM integration or clinical decision workflow in Scenario Lab.

If the browser lacks WebGPU, storage or sufficient memory, it must fail visibly. Invalid output or unknown citations cannot generate a replacement report. Public-source network/CORS failures cannot be hidden by invented records. Export records before clearing site data; browser-local storage is not a backed-up server database.

Medical validation would require a separately defined intended use, study protocol, expert evaluation and relevant clinical/regulatory process. Passing build and integration checks does not provide that validation.
